# 后端架构与维护约定

## 目录职责

```text
Backend/
├─ prisma/
│  ├─ schema.prisma       # 数据实体、索引、唯一约束和表关系
│  └─ seed.ts             # 可重复执行的系统角色、权限和管理员初始化
├─ src/
│  ├─ modules/            # 按业务域组织，禁止跨模块直接引用路由文件
│  │  └─ <module>/
│  │     ├─ *.routes.ts   # HTTP 路径、中间件、响应状态
│  │     ├─ *.schema.ts   # Zod 输入校验及输入类型
│  │     └─ *.service.ts  # 业务规则、事务和 Prisma 查询
│  ├─ middleware/         # 认证、授权、校验、请求上下文和错误出口
│  ├─ services/           # 被多个业务模块共享的领域无关服务
│  ├─ lib/                # Prisma、HTTP 等底层适配
│  ├─ config.ts           # 环境变量的唯一读取入口
│  ├─ app.ts              # Express 装配，不监听端口
│  └─ server.ts           # 进程启动与优雅退出
└─ README.md              # 部署、启动和外部使用说明
```

## 依赖方向

`routes -> schema/service -> lib`。service 不依赖 Express Response，因而可以在单元测试、队列任务和定时任务中复用。模块之间如果需要协作，抽取明确的公共 service，避免互相导入内部实现。

## 注释标准

- 注释说明“为什么这样做”、安全边界、事务范围和不明显的业务约束。
- 类型、函数名已经表达清楚的代码无需逐行翻译式注释。
- 对外 service 使用 JSDoc；临时方案必须写明移除条件，禁止只写 `TODO`。
- Prisma 模型用 `///` 描述业务语义，字段名不能表达的单位应写入字段注释或名称，例如 `durationSec`。

## 新模块模板

新增业务时创建 `src/modules/<name>`，至少包含 routes、schema、service 三个文件，再由 `app.ts` 挂载路由。路由中不要直接调用 Prisma；所有客户端输入必须先通过 schema；需要同时更新多张表的写操作必须放进 `$transaction`。

## 高风险业务约束

- 金币、佣金、提现：余额和不可变流水在同一事务更新，外部请求携带唯一 `bizId`。
- 支付与广告回调：先验签，再以平台交易号做幂等处理，成功入账后才返回成功。
- 后台写操作：声明按钮级权限码，并在业务事务中写入审计日志。
- 密码、Token、支付宝账号等敏感字段：日志中禁止记录原文，接口响应使用字段白名单。
- 删除内容：优先使用状态下线或软删除；物理删除必须确认关联数据的保留要求。
