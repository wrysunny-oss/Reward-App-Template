# 线上故障排查手册

本文适用于 `/opt/hanle/app` 下的 Docker Compose 部署。排查时先记录发生时间、操作账号、接口地址和响应中的 `requestId`。

## 1. 快速检查

```bash
cd /opt/hanle/app/deploy

docker compose --env-file .env -f docker-compose.production.yml ps
curl http://127.0.0.1:3000/ready
curl https://api.nantongjiangnan.cn/ready
```

判断方式：

- 容器不健康：先看 Backend 或 MySQL 日志。
- 本机 `/ready` 正常、HTTPS 异常：检查 Nginx、证书、DNS 和安全组。
- 两个 `/ready` 都正常：根据 `requestId` 查询具体业务请求日志。

## 2. Backend 日志

最近 300 行：

```bash
docker compose --env-file .env -f docker-compose.production.yml logs --tail=300 backend
```

持续查看：

```bash
docker compose --env-file .env -f docker-compose.production.yml logs -f --tail=200 backend
```

退出实时日志使用 `Ctrl+C`，不会停止容器。

## 3. MySQL 日志

```bash
docker compose --env-file .env -f docker-compose.production.yml logs --tail=300 mysql
```

如果 Backend 显示数据库连接失败，同时检查：

- `deploy/.env` 中数据库名、用户和密码是否与首次创建时一致。
- MySQL 容器是否为 `healthy`。
- `/data/hanle/mysql` 的磁盘空间和权限。
- 不要修改已有数据目录对应的 `MYSQL_*` 密码后直接重建，初始化变量不会自动修改库内账号密码。

## 4. Nginx 与 502

宝塔站点日志通常位于：

```text
/www/wwwlogs/api.nantongjiangnan.cn.log
/www/wwwlogs/api.nantongjiangnan.cn.error.log
```

查看错误：

```bash
tail -n 200 /www/wwwlogs/api.nantongjiangnan.cn.error.log
nginx -t
```

出现 502 时确认 Backend 监听 `127.0.0.1:3000`，并且 API 站点反向代理目标也是 `http://127.0.0.1:3000`。

## 5. Docker 构建失败

输出完整构建过程：

```bash
docker compose --env-file .env -f docker-compose.production.yml build --no-cache --progress=plain backend
```

如果出现：

```text
Cannot find module '/scripts/sync-product-config.mjs'
```

说明服务器仍使用旧版 Dockerfile 或 Compose 构建上下文。执行：

```bash
cd /opt/hanle/app
git pull --ff-only origin main
git status

cd deploy
docker compose --env-file .env -f docker-compose.production.yml up -d --build backend
```

新版 Compose 的构建上下文应为仓库根目录，Dockerfile 应使用 `npm run build:docker`。

## 6. 数据库迁移失败

```bash
docker compose --env-file .env -f docker-compose.production.yml --profile tools run --rm migrate
```

生产环境只使用 `prisma migrate deploy`，不要执行 `prisma migrate dev`。迁移前先备份数据库；如果提示迁移历史不一致，不要手工删表或修改迁移记录，先保存完整错误输出再处理。

## 7. 管理后台异常

- 登录频繁过期：确认 `deploy/backend.env` 包含 `ADMIN_ACCESS_TOKEN_EXPIRES_IN=24h`、`REFRESH_TOKEN_EXPIRES_IN=30d`，并且 Backend 与 Admin 都已重新发布。
- 页面刷新 404：Admin Nginx 需要 `try_files $uri $uri/ /index.html;`。
- 图片上传成功但不能预览：确认 `/uploads/` 地址指向 API 域名，并检查上传目录映射与 Nginx。
- 修改前端代码没有生效：重新构建 Admin，并用新 `dist` 内容替换站点文件；清理浏览器缓存后复测。

## 8. APP 没有更新提示

依次确认：

1. 新 APK 的 `versionCode` 已递增。
2. 管理后台版本记录的平台为 Android、已启用且已到发布时间。
3. 后台 `versionCode` 与 APK 一致，并高于设备当前版本。
4. APK 下载地址是可公开访问的 HTTPS 地址。
5. 灰度比例不是 0，测试设备命中了灰度范围。
6. 完全退出 APP 后重新冷启动。

普通更新点击“稍后再说”后，同一版本 24 小时内不会再次提示。

## 9. 收集信息

无法立即定位时保留：

- `docker compose ps` 输出。
- Backend、MySQL 最近 300 行日志。
- Nginx error log 对应时间段。
- 接口 URL、HTTP 状态码、响应正文和 `requestId`。
- 当前 Git commit：`git rev-parse --short HEAD`。
- APP 的 `versionName`、`versionCode`、设备系统版本和复现步骤。

日志中如果出现 AccessKey、Token、手机号、支付宝信息或私钥内容，对外发送前必须脱敏。
